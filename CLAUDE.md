## Dev loop

- Git: this folder is a repo pushed to the private GitHub repo `vash-silver/swgr` (`main`). Game files, build output and personal `bin/*.cfg`/`.pos` stay out (see `.gitignore`). The repo is shared privately with friends: keep character names, other players' names, local paths and chat content out of committed files. `bin/data/` (the runtime data pack) is committed: rebuild it with `tools/make-data-pack.js` after a patch. Commit and push when a feature is confirmed working. `gh` is at `C:\Program Files\GitHub CLI\gh.exe`; run it from PowerShell.

- Search text with `grep -r` over `beautified/` (strings are `file:key = value`, and a reference like `@quest/ground/x:key` maps to `beautified/string/en/quest/ground/x.txt`).
- To pull more files out of the TREs, run `tools/tre-extract.js` with a regex (the decryption tools `twofish.js`, `toc.js`, `keysearch.js`, `tre-extract.js` and `notes/tre-format.md` are gitignored on purpose: never commit them). Check `extracted/filelist.tsv` for names first.
- After a client patch, re-run `tools/keysearch.js` if extraction fails (the key offset may move). Re-check the memory offsets in `notes/memory.md` too (`node tools/rtti.js original/dx12/SwgClient_r.exe CreatureObject`, then `bin/memread.exe`).
- Font mod: build with `tools/font-build.js`, compare with `tools/font-preview.js` (renders PNGs into the scratchpad), repackage into `mod/package/flytext_mod/`. The user installs it.
- Tools bundle: `bin/swgr-tools.exe` (tray app) = `swgr-tools.cs` + `overlay.cs` + `parts.cs` + `ui.cs` + `parts-overlay.cs` + `mob-details.cs` + `xp-tracker.cs` + `dps-meter.cs` + `threat.cs` + `credits.cs` + `kill-sound.cs` + `kill-streak.cs` + `mobs-panel.cs` + `flytext.cs`. Build with `build.cmd` (bundle + `swgr-parts.exe`) or `build.cmd all` (every standalone too); the commands are also in `docs/DEVELOPMENT.md`. Stop it with `taskkill //F //IM swgr-tools.exe` (it ignores a plain close request) before rebuilding, then restart it. Keep the standalone builds compiling too (`overlay.cs` + `ui.cs`, `parts.cs` alone, `parts.cs` + `ui.cs` + `parts-overlay.cs`, `parts.cs` + `ui.cs` + `mob-details.cs`, `parts.cs` + `ui.cs` + `mob-details.cs` + `xp-tracker.cs`, `ui.cs` + `dps-meter.cs`, `overlay.cs` + `ui.cs` + `threat.cs`, `parts.cs` + `ui.cs` + `credits.cs`, `overlay.cs` + `ui.cs` + `kill-sound.cs`, `ui.cs` + `kill-streak.cs`, `overlay.cs` + `ui.cs` + `mobs-panel.cs`, `ui.cs` + `dps-meter.cs` + `flytext.cs`).

- The user shares in-game screenshots via Lightshot: take the newest file in the Lightshot screenshot folder (its path is in the local Claude memory, not in the repo).

## Guardrails

- **Client memory: read, never write.** The user has SWGR approval to read client memory, but never to write or modify it in any way. Tools open the process with `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ` only. Never add WriteProcessMemory, VirtualProtectEx, CreateRemoteThread, DLL injection, debugger attach, or any other access right. Audit with grep after edits.
- Otherwise don't run, attach to or patch the client, and don't send anything to `live.swgr.org`, without asking: this is a live online server with the user's account.
- Never edit files under `C:\SWG Restoration` yourself. Hand the user a `! cp ...` command (Git Bash syntax, because `!` runs in Bash) and verify the result afterwards. The mod lives in `C:\SWG Restoration\user.cfg` + `flytext_mod\`, installed by the user. Never read or quote `auth.cfg`.
- Treat `x64/profiles/` (chatlogs, character ids) as personal data and keep it out of notes.
- Keep the Twofish key bytes out of notes; refer to the exe offset instead.

## Ship part scanner (done, first version)

`tools/parts.cs` → `bin/swgr-parts.exe`. It walks player `+0xb8` containers, reads the ObjectAttributeManager map (RVA `0x2229418` since the 2026-10-30 patch) and rates components with the value sheet. That sheet is copied from the `swgr-ship-part-evaluator` skill / the user's Part Checker page, so keep all three in sync if the default values change. The user can override thresholds in SWGR tools → Value sheet (`bin/swgr-values.cfg`, personal and not synced; Reset to defaults deletes it). Layout: `notes/memory.md` → "Containers and the examine-attribute cache". Same read-only rules as the overlay. Audit with grep after edits.

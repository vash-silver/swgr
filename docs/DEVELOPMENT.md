# Developer notes

The full reference for every tool, how it reads the game, and how the pieces were found. For installing and using the tools, see the [README](../README.md). Paths are relative to the repo root.

## The client

**Target:** the SWG Restoration (Star Wars Galaxies pre-CU private server) client, installed at `C:\SWG Restoration`.
- `SWG Restoration.exe`: Electron launcher (patcher). Not analysed.
- `x64/SwgClient_r.exe`: the 64-bit game client (34 MB, PE timestamp `0x6adbd1a2`, signed "AN OLD MAN IN THE VILLAGE, LLC"). A 32-bit `SwgClient_TC.exe` also ships.
- Data: `SwgRestoration_*.tre` + `SwgRestoration.toc` / `SwgRestoration2.toc`, encrypted. The decryption tooling is kept out of this repo on purpose.
- Login server: `live.swgr.org:44453` (`login.cfg`).

**Goals:** understand the hidden, per-player Jedi unlock (parked). Then client-side quality-of-life mods: a font mod for flytext and names, and a read-only target HP overlay.

The client actually run is the DX12 build `x64/dx12/SwgClient_r.exe` (36.6 MB). It runs with `x64/` as its working directory and reads `x64/client.cfg`.

## Local game data

The repo doesn't include the game's archives or the tool that decrypts them. The maintainer keeps a local extraction (`extracted/`, `beautified/`, both gitignored). Tools that turn it into data:

```
node tools/convert.js extracted/tre beautified                  # .stf -> key = value .txt, datatables -> .tsv
node tools/ship-part-table.js extracted/tre beautified/string/en bin/ship-parts.tsv
node tools/buff-icons.js extracted/tre beautified/datatables/buff/buff.tsv beautified/string/en/ui_buff.txt bin/buff-icons
node tools/make-data-pack.js                                    # copies what the panels read into bin/data/
```

At runtime the panels read `bin/data/` first (`GameData` in `ui.cs`), then `../beautified/`. Without either, names fall back to raw keys and the buff row has no icons. Rebuild and commit `bin/data/` after a game patch that changes names, buffs or ship components.

## Flytext font mod

Replaces the `verdana_bold` bitmap family, plus regular `verdana_18` (overhead names) and `verdana_22` (combat flytext), with Encode Sans Medium (Questlog's font family; SemiBold looked too heavy in game under the engine shadow) at stock cap height with no baked shadow or outline (the game already draws its own drop shadow under names, so a baked one doubles it). Names and flytext (`verdana_18`/`22`) are rendered at 1.15× (`--hires 1.15`): the client draws every UI bitmap at texel size × `uiScalingFactor` (1.75 here), so extra texels make text both sharper and bigger, and 1.15× was the user's preferred balance (1× soft, 1.4× and 2× too big). The bold UI family (windows, tables, buttons) is also at 1.15× since 2026-10-30. It fits the mission browser's rows and buttons, but it's still a 1.75× bilinear stretch (soft edges, slightly uneven stems from grid-fit hinting). Untried improvements: `--hint aa`, or `uiScalingFactor` 1.0 with fonts at 1.75× (which shrinks all other UI art). The previous Titillium Web SemiBold package is kept in `mod/package-titillium/`. Each size keeps its name, Leading and baseline. See `notes/ui-fonts.md`. Rebuilding it needs the stock fonts from a local extraction (`extracted/tre/texture/font`, `ui/font`); the built package is in `mod/package/`.
```
node tools/font-build.js mod/fonts/EncodeSans-Medium.ttf extracted/tre mod/build --outline 0 --shadow 0 --cap 0 --hires 1.15   # --outline, --shadow, --cap, --track to tune
node tools/font-build.js mod/fonts/EncodeSans-Medium.ttf extracted/tre mod/build-world --face verdana --sizes 18,22 --outline 0 --shadow 0 --cap 0 --hires 1.15
# package = mod/build + mod/build-world merged into mod/package/flytext_mod/
node tools/font-preview.js extracted/tre preview.png "Encode Sans Medium=mod/build" --sizes 14,18,22
```
Install: copy `mod/package/user.cfg` and `mod/package/flytext_mod/` into `C:\SWG Restoration\`. Confirmed in game: bold UI text, overhead names and combat flytext change.

## SWGR tools (the bundle)

`bin/swgr-tools.exe` is a single tray app hosting everything below. Double-click the tray icon (or tray → Open SWGR tools) for the main window: **Overlays** (on/off for each overlay, HP style and preview), **Appearance** (text size and font, with font samples) and **Part scan** (the scanner report). Closing the window keeps the app in the tray; "Exit SWGR tools" quits. `swgr-tools.exe --render-main out` saves the three pages as `out-0..2.png`. The tray menu also has on/off toggles for the **target HP overlay**, the **mob details panel** and the **part verdict panel**, the HP overlay's style submenu, **Text size** (100–200%) and **Font** for all three overlays (Encode Sans is bundled in `bin/fonts/` and loaded privately via `UiLook.MakeFont`, so it needn't be installed; the HP overlay keeps each style's own fonts until a font is picked; Terminal stays monospace) (also on each panel's right-click menu, saved in `bin/swgr-ui.cfg`; `swgr-mob.exe --render-fonts out.png` previews every font), and **Scan inventory for ship parts...** (a window with the scanner report; double-clicking the tray icon opens it too). All windows are DPI-aware (`UiLook.EnableDpi` at the start of each `Main`), so Windows no longer bitmap-stretches them at 150% scaling: panels multiply their scale by `UiLook.Dpi` and use pixel-unit fonts (`UiLook.PanelFont`), and the main window's pixel sizes go through `UiLook.D/Pad/Sz`. Which panels are on is saved in `bin/swgr-tools.cfg`; each panel keeps its own `.pos` file. Everything is read-only.

**Opacity:** every overlay is a per-pixel alpha (layered) window (`LayeredForm` in `ui.cs`). Each repaint draws the panel into a 32-bit bitmap, the background at **Background opacity** and the panel's own `OnPaint` on top, then hands it to Windows (`UpdateLayeredWindow`), which blends it over the game at **Overall opacity**. So the background can be see-through while text, bars and icons stay solid. Each window has its own pair: set them from that panel's right-click menu, or on the Appearance page after picking the window (background 100/85/70/55/40/25/0 %, overall 100–50 %). They're saved per window as `target|self|mob|parts|xp|dps=back,panel` in `bin/swgr-opacity.cfg` (personal, not synced). A fully clear background is kept at alpha 1, so the panel can still be dragged. Confirmed live on 2026-11-01: the self overlay at 40 % background showed the game through it, with its text and bars unaffected.
```
cd tools
csc -nologo -target:winexe -platform:x64 -optimize -main:SwgrTools -win32icon:swgr-tools.ico -out:../bin/swgr-tools.exe swgr-tools.cs overlay.cs parts.cs ui.cs parts-overlay.cs mob-details.cs xp-tracker.cs dps-meter.cs threat.cs credits.cs kill-sound.cs kill-streak.cs mobs-panel.cs flytext.cs
```
The exe icon (`tools/swgr-tools.ico`, 16–256 px) is the tray icon's teal ring and gold dot. Regenerate it with `powershell -ExecutionPolicy Bypass -File make-icon.ps1` from `tools/` if you change `MakeIcon()`.
The standalone builds below still work (useful for testing one piece).

## Kill sound

`kill-sound.cs` plays a short sound when a mob you were fighting dies: one that was attacking you, or your target once it's damaged, within the last 6 s (80 m). Death is health 0 or posture 14 Dead (`+0x988`, `notes/memory.md`). Kills in the same 200 ms tick share one sound, and a corpse only rings once. A groupmate's killing blow on a mob that was on you counts too. Tools window → Overlays → Kill sound, or tray → Kill sound: Off, Chime (default), Ping, Coin, Thud, Click (picking one plays it) and Volume 25/50/75/100 %. Saved in `bin/swgr-killsound.cfg` (personal, not synced). The sounds are synthesised in code, with no audio files. `swgr-killsound.exe --wav <dir>` writes them as .wav files. Standalone: `csc -nologo -target:winexe -platform:x64 -optimize -main:KillSound -out:../bin/swgr-killsound.exe overlay.cs ui.cs kill-sound.cs`. Not yet confirmed in game.

## Nearby mobs panel

`mobs-panel.cs`: the live NPCs/creatures around you (players left out) that are fighting or hurt (by default; Show can also list every mob, or only ones in combat), each with a full HP bar, in the Questlog look of the target overlay (same bar colours, set under Colours on the Overlays page). Each row: name, level (or "→ <player>" when it's attacking someone else), current / max health and distance, with a damage trail when it takes a hit. A green stripe means it's on you, a red stripe that it's on another player (a loose one, so it needs a taunt), and your current target is outlined in blue. Header: how many are listed, how many are on you and how many are loose. Settings (Tools window → Overlays → Nearby mobs, or right-click it): Show aggro or damaged (default: attacking someone, or below max health) / in combat only / all mobs, Sort fighting first (loose, on you, your target, then the rest, each by distance) / closest / lowest HP, Range 30/50/80/120 m, Rows 5/8/12/16, Always visible (otherwise it hides when nothing is in range). Saved as `x,y,show,sort,range,rows,always` in `bin/swgr-mobs.cfg`. Source: the client's nearby-creature vector, each creature's health, level and combat target (`GameReader.ReadNearby`, `notes/memory.md` → "Aggro"), read-only like everything else. `swgr-mobs.exe --render out.png` draws a sample in the three sort orders. Standalone: `csc -nologo -target:winexe -platform:x64 -optimize -main:NearbyMobs -out:../bin/swgr-mobs.exe overlay.cs ui.cs mobs-panel.cs`. Not yet confirmed in game.

## Kill streak banner

`kill-streak.cs`, fed by the kill sound's detector (`kill-sound.cs`, `Killed` event; no memory access of its own). Floating text over the game, no panel: the streak count (kills less than the window apart, 20/30/45/60 s, default 30), popping with a glow in the tier colour on each kill, and the tier title beside it (Kill, Double, Triple, Hot streak 5, Relentless 8, Merciless 12, Legendary 20, Galactic threat 30), sliding in when the tier changes. Optional second line "<mob> killed". Click-through, top centre by default. It fades in (0.25 s, sliding up a little) on each kill, stays for the "Show for" time after your latest kill (3/5/8 s, default 5) and fades out (0.9 s); when a streak of 2+ runs out it shows "STREAK ENDED" for 3.5 s. Settings: Tools window → Overlays → Kill streak (Window, Show for, Unlock to move, Test kill, Reset session, Show the mob's name). Test kills don't count toward the session or the best. Saved as `x,y,window,hold,best,showName` in `bin/swgr-streak.cfg`. With the kill sound's "Rising pitch in a streak" (default on), each kill of a streak plays a semitone higher, up to an octave. `swgr-streak.exe --render out.png` draws five moments of a streak (and `out-name.png` with the mob line); run it without arguments for a live demo. Standalone: `csc -nologo -target:winexe -platform:x64 -optimize -main:KillStreak -out:../bin/swgr-streak.exe ui.cs kill-streak.cs`. Not yet confirmed in game.

## Combat text (floating numbers)

`flytext.cs`: our own floating combat text, because the game's can't be moved. Three zones, each its own click-through window: **damage you deal** (right of centre by default), **damage you take** (left) and **heals** (under it). Numbers float and fade. Crits are bigger and gold (red when you take them) with a pop, glances are smaller and dimmed, blocked hits get a small "blocked" tag, DoT ticks are small and coloured by damage type (bleeding red, poison green, fire orange, acid yellow, energy blue, …), and misses show "Miss". Brief-mode misses have no target ("X misses"), so a mob's miss counts as one at you if that mob hit you in the last 8 s. Heals on you are green, your heals on others lighter with "→ name", and drain life is a teal "+N drain".

Settings (Tools window → Overlays → Combat text, or right-click an unlocked zone): Style **Clean** (thin dark edge + soft shadow), **Outline** (crisp black outline) or **Glow** (soft halo in the number's colour). Motion **Scroll up**, **Scroll down** or **Fountain**. Weight Regular / Medium (Encode Sans Medium, the in-game font mod's face; bundled in `bin/fonts/`) / SemiBold. Size Small / Normal / Large / Huge (on top of the overlays' text size). Each zone on/off, Show names (target or attacker after the number), Merge DoT ticks (ticks of one type on one target within 0.45 s become one number with ×N), Show misses, Unlock to move (dashed frames you can drag) and Test (a scripted burst in every zone). Saved in `bin/swgr-flytext.cfg` (personal, not synced). Overall opacity comes from the Appearance page ("flytext" key). Turn the game's own numbers off with Options → Combat → Show Damage Numbers over Others / over Self.

Source: the chat log only, through its own `CombatTracker` tail (polled every 60 ms, starting at the end of the file), so it needs combat messages on like the DPS meter. The game writes combat lines as they happen. Standalone: `csc -nologo -target:winexe -platform:x64 -optimize -main:FlyText -out:../bin/swgr-flytext.exe ui.cs dps-meter.cs flytext.cs`. `swgr-flytext.exe --render out.png [background.png]` writes `out.png` (the three styles) and `out-motion.png` (the three motions). Not yet confirmed in game.

## Credits tracker

`credits.cs` shows your cash, bank and total, the credits earned and spent this session, the net per hour (session net ÷ session time, so it falls while nothing comes in), and the last six changes. It reads every 200 ms and the balances follow each read; the panel also redraws every second. Moves between cash and bank are listed (grey) but not counted. A change is only committed to the log and totals once the reading has held still for 0.8 s, so a two-step transfer doesn't show as a loss plus a gain. A different character, or a relog, takes the new balances without counting them. The session (start time, earned, spent, change log) is saved in `bin/swgr-credits.cfg` (personal, not synced) and survives restarts of the tools and relogs: only Reset session (right-click, or Tools window → Overlays → Credits) starts a new one. The session clock counts m:ss, then h:mm:ss. Source: two int fields on your CreatureObject (`notes/memory.md` → "Credits"). Preview: `swgr-credits.exe --render out.png`. Standalone: `csc -nologo -target:winexe -platform:x64 -optimize -main:CreditsTracker -out:../bin/swgr-credits.exe parts.cs ui.cs credits.cs`.

## Threat panel and aggro strip (tanking)

`threat.cs`, shown while a mob near you is attacking a player. Mobs on someone else ("loose", need a taunt) come first in red, with the name of the person they're hitting, then the mobs on you in green, each with a thin HP line and distance. The header counts both. Right-click → Range (30/50/80/120 m, default 50, saved as the third field of `bin/swgr-threat.pos`). The target overlay also shows a strip under the panel, with a matching frame: **ON YOU** (green) or **ON <name>** + "taunt" (red), for NPC targets only. The self overlay shows **N MOBS ON YOU** (within 100 m). `swgr-overlay.exe --render-aggro out.png` and `swgr-threat.exe --render out.png` preview them. Source: each creature's combat target pointer, read from the client's list of nearby creatures (`notes/memory.md` → "Aggro"). Standalone: `csc -nologo -target:winexe -platform:x64 -optimize -main:ThreatPanel -out:../bin/swgr-threat.exe overlay.cs ui.cs threat.cs`.

## Mob details panel

`mob-details.cs`, shown while you have a target. It shows the name (generic mobs resolved through the string tables in the data pack), level, template, Health/Action/Mind bars, condition tags (Aggressive / Attackable or Invulnerable / Talks / Quest / Player), posture (e.g. Dead), distance, faction, and the con text once you've examined the mob. Offsets: `notes/memory.md` → "Creature details". `--render out.png` previews sample panels. Standalone: `csc -nologo -target:winexe -platform:x64 -optimize -main:MobDetails -out:../bin/swgr-mob.exe parts.cs ui.cs mob-details.cs`.

## Part verdict panel

`xp-tracker.cs`, the XP tracker: experience earned this session per xp type and per hour, read from the PlayerObject's experience map (`notes/memory.md` → "Experience"). Gains add up each increase, so spending xp on a skill doesn't reduce them. Right-click it to reset the session or show every type. Standalone: `csc -nologo -target:winexe -platform:x64 -optimize -main:XpTracker -out:../bin/swgr-xp.exe parts.cs ui.cs mob-details.cs xp-tracker.cs` (`--render out.png` for a preview, `--print` writes the current totals to `bin/swgr-xp.txt`).

`dps-meter.cs`, the DPS meter (ground combat). It doesn't read client memory at all: it tails the game's own chat log (the newest `x64\profiles\<account>\<server>\*_chatlog.txt`) and parses the `[Combat]` lines. It needs combat messages on (Options → Chat → Combat Message Filter: "Self", or "Group" for the party view; the Combat Message Range slider next to it limits how far away groupmates are heard); brief lines (`X hits Y 1047 pts`, `crits`, `glances`, `hits (blocked)`, `misses`, `heals … for N points of damage`), DoT ticks (`X has caused Y to take N points of bleeding damage`, and `X has taken N points of poison damage` with no source), `drains life from` and verbose `uses <ability> on …` lines all parse. Glances and DoT ticks were added on 2026-11-03: before that they were dropped, so damage dealt and taken read low. Ticks count toward damage but not hit counts, and show as `<type> (DoT)` in damage by ability. Drains aren't counted in the meter. The log writes every combat line twice, always as adjacent copies (one per chat window showing Combat), so every second identical line is dropped. A real repeat arrives as another pair. A fight starts with the first damage in the log and ends after 10 s without any. The panel shows the current fight (or the last one), with DPS, damage dealt, hits/crits/blocked/missed, max and average hit, accuracy, damage taken, healing received and damage per target. Right-click → "Show session totals" or Reset.

**Styles:** right-click → Style. **Questlog** (the default) copies Questlog's Aion 2 damage meter, taken from its renderer (`renderer/aion-2/_nuxt`, the dps-meter page and its `CombatBar` component, read in the scratchpad, not stored here). It's a 340 px rounded panel in Questlog's palette (gray-800 panel, gray-500 border, gray-700 row track, text 250/220/175, accent 66,153,225). The header has the fight time and the total DPS in the accent colour, then tiny DPS / Share / Damage labels, then 30 px rows. Each row's fill is a gradient from 22% to 42% of the row colour mixed into gray-700, ending in a 2 px line of the full colour with a 10 px glow; the text has a 1 px black shadow, your row has a ▸, DPS is bold and share and damage are smaller. Numbers are formatted like Questlog's (12.3K / 1.23M). Fonts are Encode Sans Regular/SemiBold (bundled), as Questlog uses. SWG has no class icons, so each row has a coloured initial badge: you are always the accent blue, and groupmates get a stable colour from their name. "Show targets instead of party" switches the rows to your targets. **Classic** is the earlier layout with hit stats and both lists. The style is saved as the third field of `bin/swgr-dps.pos`.

**Damage page:** the tools window (tray → Open SWGR tools → Damage) has the same data with more room. On the left: Session, the fight in progress, then every finished fight newest first (time, length, DPS, main target). On the right: the selected fight in full (DPS / dealt / taken / healed tiles, hit stats, Party, every target and, with verbose combat messages, every ability), plus Reset session. It polls the log itself, so it keeps updating while the panel is off. `swgr-tools.exe --render-main out` renders it with a sample group fight.

**Party:** with Options → Chat → Combat Message Filter on "Group", a Party section lists you and each groupmate (pets too), with DPS and their share of the group's damage. Sides come from who hits whom: enemies are what you hit and what hits you, and anyone else who hits an enemy (or gets hit by one) is on your side. In the bundle, "you" is your character name read from the game (`Parts.PlayerName`, read-only; it attaches if no other panel has). The standalone build falls back to whoever deals the most hits, which can pick a busier groupmate. Standalone: `csc -nologo -target:winexe -platform:x64 -optimize -main:DpsMeter -out:../bin/swgr-dps.exe ui.cs dps-meter.cs` (`--render out.png` previews it; `--parse <chatlog> <out.txt>` replays a log and writes every fight's summary). A replay of the 2026-10-31 log found 45 fights, e.g. a dewback lair fight of 51 s, 55,776 dealt, ~1,094 DPS. The chat log is personal data: the meter only reads it locally and nothing from it goes into the notes.

`parts-overlay.cs`, shown when you click an item in the inventory window. It reads the item in the info panel (chain in `notes/memory.md`), looks up its cached examine stats, and shows the verdict, the reason and every stat against its threshold. It's hidden when nothing is selected. Drag it to move. `--render out.png` previews sample panels. Standalone: `csc -nologo -target:winexe -platform:x64 -optimize -main:PartsOverlay -out:../bin/swgr-parts-overlay.exe parts.cs ui.cs parts-overlay.cs`. `swgr-parts.exe --selected` prints the same verdict in the console.

Vendor and bazaar items: opening **Item Details** on a ship component makes the panel rate that item instead; whichever you clicked last (inventory item or vendor details) is shown, and closing the details window returns to the inventory selection. The details carry the stats but no level and no name, so both come from the component's object template via `ship-parts.tsv` (template, cert level, name). It ships in the data pack (`bin/data/ship-parts.tsv`); `tools/ship-part-table.js` rebuilds it from the extracted `object/tangible/ship/(components|crafted)/**/shared_*.iff` templates (see Local game data).

The panel shows the template's name, not the seller's custom name. `swgr-parts.exe --vendor [-v]` prints the open item's verdict; `--vendor-watch [seconds]` logs every change of the details map (50 ms polling). Reported 2026-11-03: switching items very fast sometimes left the panel on an old item; not reproduced yet.

## Target HP overlay

`bin/swgr-overlay.exe` (source `tools/overlay.cs`) is a small always-on-top window showing the current target's name and current/max HP, read live from client memory. It's **read-only**: the process handle has only query and VM-read rights, and the user has SWGR approval to read (never write) client memory. Right-click (or the tray icon) → Style picks one of six looks (Classic, Holo, Minimal, Terminal, Radial, Questlog: the DPS meter's rounded gray panel and glowing gradient rows, in Encode Sans, with brighter bar colours (fill 50–72 % of the bar colour, halfway between the DPS meter's dim fill and full colour): Vivid by default, or Neon, Game or the DPS meter's own soft Questlog colours, set under Colours on the Overlays page and saved in `bin/swgr-ql.cfg`; `--render-ql out.png` compares them); `swgr-overlay.exe --render out.png` draws all six with sample data. Position, scale and style are saved in `bin/swgr-overlay.pos`.

**Self overlay:** a second copy of the same window that shows your own character (Health, Action and Mind with numbers, level, your buffs and debuffs with timers and tooltips, damage trail). It has its own position, size and style in `bin/swgr-self.pos`; right-click it for the style. In the bundle it's "Self overlay" in the tray menu and on the Overlays page. Every style shows Action and Mind as current / max (Classic on taller bars, Holo and Terminal per row, Minimal on one line under the hairlines, Radial in the sub line, Questlog as two half-width rows), on both the target and self overlays.

**Damage trail:** when a bar drops, the fill moves at once and the lost chunk stays as a lighter band (light red on HP). It holds for 0.4 s, and each new hit restarts the hold so a combo reads as one chunk, then eases down. Heals just move the fill, and a new target snaps without animating. It applies to every bar in every style, ship rows included (Terminal draws the band as `=`). Repainting runs at about 60 fps only while a band is moving. `swgr-overlay.exe --render-trail out.png` draws a filmstrip of one hit in every style. Tuning constants: `TrailHold`, `TrailTau`, `TrailFloor` in `overlay.cs`.

**Lairs and other tangibles:** a lair (or any targetable object with hitpoints, e.g. a turret) shows the same panel with one health bar (max − damage taken) and no Action/Mind, level or buffs. Generic mobs now get their real name from the string tables instead of "Target". Layout: `notes/memory.md` → "Lairs and other tangibles".

**Space targets:** when the target is a ship, the same window switches to a taller ship panel in the chosen style. It shows the name, type and tier (e.g. "Mercenary Cruiser / HC-556 Light Cruiser / Tier 3"), the distance from your ship, the component you've targeted on it (green row on top, as in the game), and Shields / Armor / Systems / Chassis bars computed as the game's space target box does (rounded down, checked against the game in a fight). Every row shows current / max next to the percentage. Hovering lists the front/back shields, the hull and every component's armor and hitpoints, with disabled components marked. Right-click → "Preview ship (5 s)" shows a sample; `--render` draws the ship panels in a second column. Layout: `notes/memory.md` → "Ships".

**Buff row:** under the panel, the target's buffs (your own when you target yourself) as icons: debuffs first with a red frame, stack count top-right and time left underneath. Hovering shows the same tooltip as the game: Time Remaining (hh:mm:ss), name, description and effect lines, including build-a-buff and city values read from the buff itself. It reads the CreatureObject buff map at `+0x1508` (see `notes/memory.md` → Buffs). Icons and names come from `bin/data/buff-icons/` (598 icons plus `buffs.tsv`; a local `bin/buff-icons/` also works), built by
```
node tools/buff-icons.js extracted/tre beautified/datatables/buff/buff.tsv beautified/string/en/ui_buff.txt bin/buff-icons
```
(it needs the icon atlases from a local extraction: `--list-sources` lists them). The icons ship in the data pack. Timers need the game clock, which the overlay calibrates itself: when a buff lands on you or your target while it's watching, end − duration = game time now. The offset is saved in `bin/swgr-clock.cfg` and dropped if an active buff contradicts it (e.g. after a server restart). The game clock pauses while you're logged out (end times stay put; seen 2026-11-01), so the file also keeps when a character was last seen, and after a gap a contradicted offset is first retried shifted by that gap. `memread buffs <offset>` lists the player's buffs with the time left under an offset. Bulk-restored buffs (zoning, relogging) once miscalibrated it, so a sample only counts when one or two buffs appear while others stay, and the result fits every active buff. Until then the icons show no timer. `bin/memread.exe` (`tools/memread.cs`) is the matching inspection CLI. The offsets in `notes/memory.md` are specific to the current DX12 client build, so re-verify them after a client patch.

## Ship part scanner

**Value sheet page** (SWGR tools → Value sheet): edits the 1M+ thresholds per component type and level (≥ at least / ≤ at most is fixed per stat). An empty cell means no requirement; a level with no values isn't on the sheet. Edits apply at once (scan and verdict panel) and save to `bin/swgr-values.cfg` (`type<TAB>level<TAB>stat<TAB>value`, the whole sheet). **Reset to defaults** deletes that file. The built-in defaults stay in `tools/parts.cs` (`BuildSheet`), and the comparison per stat is in `OPS`.

`bin/swgr-parts.exe` (source `tools/parts.cs`) lists the ship components in your inventory and bags and rates each one against the 1M+ credit value sheet. It uses the same thresholds and verdicts as the `swgr-ship-part-evaluator` skill and the "SWGR Part Checker" page. It's **read-only** (query and VM-read handle only). It reads the client's examine-attribute cache, so open the inventory, and any bag, before running it. `-v` shows every stat; `--all` also lists cached components that aren't yours (e.g. ones you examined on a vendor). Memory layout: `notes/memory.md`.

Verdicts (since 2026-11-01): a part is **VALUABLE** if it clears at least one threshold for its type and level. Buyers want parts that excel at a single stat, so it doesn't need to clear them all; the sub-line names the stats it clears. **CLOSE** means nothing clears but one stat misses by 10% or less. **NEED MORE** means nothing readable clears and some stats aren't cached. **NOT VALUABLE** means everything fails, or the type/level isn't on the sheet (boosters never are).
```
cd tools
csc -nologo -platform:x64 -optimize -out:../bin/swgr-parts.exe parts.cs
```
